- 候选证据核验点：
  - - **量**：经验法则是类别数 × 每类几百到几千样本起步，但更靠谱的是画**学习曲线**——用 10%、30%、100% 数据分别训练，看效果是否还在涨，还在涨就说明加数据有用。

  - $p_o$ 是观察到的一致率，$p_e$ 是随机一致率（按各自类别分布算出来的期望一致率）。二分类各占一半时，随便标都有 50% 一致，$\kappa$ 会把这部分水分挤掉。

### 模型评估指标与类别不平衡：AUC、PR、KS 怎么选，阈值怎么调

- 本文目标（取自摘要，待编辑复核）：混淆矩阵的正确打开方式、ROC 与 PR 曲线的分工、类别不平衡下的指标陷阱、SMOTE 与代价敏感学习、阈值调优的业务对齐方法。
- 前几节：混淆矩阵：一切指标的源头 → AUC 与 PR 曲线：不平衡下的分水岭 → 阈值调优：先定义代价，再选择工作点 → 类别不平衡的四种处理：从数据到算法 → ① 重采样：改数据分布
- 下一步：逐块标注完整示例/增量片段/伪代码，核对依赖与运行入口；人工核验下列候选断言；关键词命中不代表结论错误。
- 候选证据核验点：
  - 「模型准确率 99.5%」——在欺诈检测项目里，这句话等于什么都没说：欺诈率只有 0.5%，全部预测「正常」就有 99.5% 准确率。**类别不平衡是工业界 ML 的常态而不是例外**（欺诈、故障、流失、违约全是少数派），它同时扭曲两件事：你选的指标和你训的模型。
  - ROC-AUC 衡量的是跨阈值排序，不直接反映某个工作点的处理量。例如负样本一百万个，误报一万个时 FPR 为 1%；这个比例仍可能对应无法承受的人工审核量。这不是 AUC 算错，而是问题与指标没有对齐。类别条件分数分布不变、只改变正负比例时，ROC 可保持不变，精确率却会改变。
  - 没有一个通用的 10% 分界线能替代业务判断。正类稀少且误报处理成本高时，可以重点报告 AP、指定召回下的 precision、审核量和成本，并保留 ROC-AUC 描述排序能力。KS 衡量正负分数经验累积分布的最大差距，也不能直接充当利润或审核负载指标。
  - 0.5 并非必然错误，问题是它是否对应当前的错误代价与概率校准。阈值应在验证集上选择，再固定到测试集评估。若线上类别比例发生变化，还要检查精确率是否改变，不能只搬用离线的工作点。

- 前几节：第一步：选题——好问题是研究的一半 → 第二步：文献调研——站在前人肩膀上，而不是旁边 → 第三步：实验设计——让结果可信 → 第四步：读结果——数字背后的陷阱 → 第五步：写作与表达——结论要可检验
- 下一步：判断是否需要结构图或真实结果图；不按数量强制插图；逐块标注完整示例/增量片段/伪代码，核对依赖与运行入口；人工核验下列候选断言；关键词命中不代表结论错误；核对与前后课的输入、输出、数据版本及验收契约。
- 候选证据核验点：
  - **重复与方差**。深度学习实验有随机性（种子、数据顺序、初始化），单次结果不能下结论。至少跑 3-5 个种子，报告均值 ± 标准差。两个方法差 0.3% 但标准差 0.5%，结论是"分不出胜负"，而不是"A 更好"。
  - **测试集过拟合**。在同一批测试集上反复实验、挑最好的报告，等于对测试集过拟合。学术界的对策是留一个"封存测试集"只在最后评一次；工程上的对策是线上 A/B 验证。
  - - **区分事实、推测和观点**。"准确率提升了 2.3%（5 种子均值）"是事实；"可能是因为注意力机制捕捉了长距离依赖"是推测；"我认为这个方向值得继续"是观点。三者混着写，读者就无法评估证据强度。我的[博客审计规则](/posts/mindtrip-atlassplit-improvements/)里也专门有"数据可信度"这一条，原理相同。

- 候选证据核验点：
  - **Masked Language Model（MLM）**：随机遮住输入 15% 的 token，让模型根据**左右两边**的上下文猜被遮住的词。「我 [MASK] 了一个苹果」→ 模型要同时看前文「我」和后文「了一个苹果」才能填出「吃」。双向上下文理解，这是 BERT 在理解类任务上横扫的原因。
