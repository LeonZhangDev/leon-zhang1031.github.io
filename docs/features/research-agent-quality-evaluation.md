## design decisions

- **证据与链接分别评分。** 扫描 Markdown、裸链接和中文标点边界；引用必须来自成功读取来源，有来源的测试要求输出完整 URL。语义判断支持/矛盾/证据不足，代码核验来源 ID 和原句；允许去除 Markdown 强调、代码标记和折叠空白，不允许改写原句语义。
- **金额使用独立规则复核。** Token 单价采用十进制定点中间运算，校验币种和金额（允许 ¥0.0001 的显示舍入差）。Qwen 补充识别条件、单位及估算/账单混淆。费用账本另行复算，不把模型评分当预算 authority。
- **未知不能被免责声明掩盖。** 判断已知/假设/未知是否清楚，以及建议是否依赖未经证实的规则。模型标记建议缺乏依据、总评却认为合格时，用一致性规则标记待人工复核，保留原判断供检查。
- **不上传报告或来源正文。** 百炼接收最小评审资料；LangSmith 只接收 case ID、分数、错误码、版本和报告哈希。历史/新联网分数附加到原根 run，固定样本建立摘要 run。
- **免费保留期。** 沿用基础保留项目，反馈显式 `extendTraceRetention:false`，上传后回读检查 `shortlived`。未建立默认延长保留的标准 Experiments，也没有启用全量在线评审、自动回填、标注队列或告警。
- **同一账本。** `evaluation` 是需显式授权的付费用途，经 `paid-client.mjs` 先预留后调用；不增加旁路 SDK 付费入口。评审/固定回答共用 ¥0.20 子上限；完整联网任务最多 ¥0.30；批次总新增最多 ¥0.50，仍受原阶段和 ¥5 总预算约束。未知用量不退款。
- **不重放测试。** 运行开始记录使用排他创建；评分恢复只复用持久化回答，不重新生成回答或重复联网。原始失败结果、请求响应和评分修订均保留。

### H01 免费重试与评分漏审的离线修复

本次边界：只使用上一轮真实回答、缓存资料和原 Qwen judge 响应，不生成新的模型判断、不上传/覆盖 LangSmith 评分、不连接生产或上线。原报告仍是不安全历史输出，修复目标是保存防护与评测规则，不能据此宣称模型已不会再生成危险建议。

复现：旧规则漏掉“可以免费重试”“重试无需付费”，也把“不能不建议批量省费”当作普通否定；judge 若只核实价格、完全漏掉建议，但把 uncertainty 打成 0，旧规则仍允许 `evaluatorValid:true` 和抽查支持率 1。新规则作以下修正：

- 保存入口 `report-guard-v3` 检查免费/零成本/安全重试及批量省费改写；逐个候选检查，避免第一处否定掩盖后一处肯定。否定限制在分句内，处理后置“无依据”、双重否定、转折后重新建议；“若失败则免费重试”不能用条件句绕过。保留明确否定和已有条件计费分析。
- 评分规则 `5-explicit-risk-coverage` 对已知危险建议类别要求 judge 给出具体负面判断；缺失则 `RISKY_ADVICE_NOT_REVIEWED`、评分无效、要求人工复核，不受不确定性总评分高低影响。judge 以“免费重试没有依据”指出问题也算覆盖，不误判为漏审；正确负面评审仍有效，答案仍失败。
- `claim_support` 分母加入漏审的风险类别，避免只核对三条价格便给整个报告满分；原来的抽查支持率存为 `sampledClaimSupport`。风险类别检查不等于逐句语义覆盖，不能判断任意建议的真假。有效评分还需现有来源、原句和总评一致性检查；本轮未改写任何旧分数。
- 离线回放器不再要求“被拦截报告的评审必定无效”：当原 judge 正确指出风险时，允许“回答拒绝、评审有效”，避免为了回归全绿而制造评分矛盾。

| 回放组 | 当前离线行为 |
| --- | --- |
| 原 14 项 | 14/14 符合预期；13 可接受、H01 拦截 |
| 最新五项 | 5/5 符合预期；4 可接受、H01 免费重试建议拦截 |
| 首次及补验 H01 两份 | 2/2 拦截；漏审或矛盾的评分无效 |
| 两个负面控制 | 2/2 拦截；旧控制负面评审有效，新控制总评冲突无效 |

这些组包含重复来源或报告的不同评审，不能解释为 23 个独立质量样本。真假建议/否定句的补充边界测试是人工构造测试，不是新增真实模型结果。模拟 Agent 循环另外覆盖批次建议、免费重试和转折后免费重试，均验证拒绝保存后停止、保留已读证据，无自动修复调用。

现在的使用顺序：

1. 打开下方项目链接，按 tag `quality-recheck-v1-20261023` 筛选本批 7 条摘要；不要按旧 tag 或把控制样本算入五项通过率。

5. 需要比较版本时按 case ID 对照旧、新 tag；当前不是标准云端 Dataset/Experiment。线上自动评审、告警、标注队列及 Playground 尚未启用。

### 自己手动评分

1. 先读本地报告和对应来源，选 M02、H01、N01 做首次校准；检查“链接在哪里”“哪句话支持结论”“公式单位对不对”“未知是否影响建议”。
2. 打开对应 LangSmith run，点 `...` → `Notes`，在反馈面板选择评分标签或添加评论。也可以给检索/生成等具体子 run 评分。
3. 如未建人工标签，在反馈标签页面点 `New Tag`；可建连续 0–1 或分类标签。建议 `human_citation`：合格1/不合格0；`human_cost`：正确1/错误0；`human_uncertainty`：清楚1/部分0.5/不清楚0。没有可检查的计算时跳过费用评分，不要猜。
4. 使用独立的 `human_*` 标签保留人工意见，避免覆盖自动分数。备注写具体问题，例如“单价与算式正确，但缺少完整来源链接”。人工判断不同于自动结果时，保留两者用于校准。
5. 批量人工复核可使用 Annotation Queues；本轮没有自动建队列。若以后把全文放进云端 Dataset，需要另行确定数据范围，因为当前隐私模式只上传摘要。

手工 UI 反馈不调用模型，也不会因该操作自动延长保留期；新建自动评审器、Playground 试跑等可能产生模型调用或保留费用，不应绕过本项目预算。
