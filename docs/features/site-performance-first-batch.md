主题切换、导航、代码复制、图片预览与评论功能。尚未部署或推送。

## Design decisions

- 浏览器立即开始全页导航，原有淡出与导航并行；返回缓存页面时恢复透明度。
- 保留头部主题防闪脚本；导航、二维码、滚动交互和粒子脚本由 Astro 构建、压缩并生成带哈希的公共资源。
- 标题与正文直接显示；保留列表、卡片等装饰性入场，减少动态效果时跳过入场计时器。
- 评论区进入距离视口 400px 的范围后检查服务，再加载 Artalk JS 与 CSS。
  直接访问 `#comments` 同样可以初始化；缺少 IntersectionObserver 时立即初始化。
- 使用 CSS 资源 URL 按需插入 stylesheet，避免 Astro 将动态 CSS 导入提升到首屏页头。
  样式加载失败会清理失败链接并允许重试；并发重试不会重复初始化。
- 阅读进度使用 `scaleX`；卡片光效每个动画帧最多更新一次。粒子绘制参数保持原值。

## Implementation notes

- `src/layouts/BaseLayout.astro`：保留静态结构与主题防闪，导入公共交互模块。
- `src/scripts/site-ui.ts`：公共交互、并行淡出与页面恢复。
- `src/scripts/constellation.ts`：从布局移出的原有粒子实现，增加明确类型与空上下文保护。
- `src/components/Comments.astro`：服务检查、按需 JS/CSS、主题同步和重试。
- `src/styles/global.css`：阅读进度改用 transform，保留原有淡出样式。
- 调整现有回归用例，在评论区进入视口后验证编辑器；安全头用例使用模拟评论响应。

### 测量方法

优化前源代码基准：`55abe8e4a1951efb1987ad92e53df28edde8964b`。
前后分别构建到 `.tmp/site-performance/before/dist` 与 `after/dist`，均为 186 页。
使用同一本地 Brotli 静态服务器、相同 ETag 与缓存策略，不改正式站点缓存。

使用 Chrome 155.0.8059.85、Playwright、Node 24.19.0；网络模拟为下载 655360 B/s、上传 131072 B/s、
60ms 延迟，CPU 放慢 4 倍。桌面视口 1440×900，手机模拟视口 390×844、DPR 2。
这是桌面 Chrome 的手机模拟，不是真实手机测试。

每个场景五组前后配对并交替顺序；每组新建独立浏览器上下文，先冷访问，再在同一
上下文热访问。首页与 Transformer 长文章、两种视口、两种缓存状态共 80 次访问。
测量截止于页面 load 后 1800ms。服务器先预热压缩缓存，浏览器冷上下文仍为空。

两版均阻断真实评论与统计域名，避免外部网络波动；未提交评论、未登录或写入真实数据。
因此结果不包含真实评论服务延迟、生产 CDN、真实用户分位数或 INP。

传输量是导航与已完成同源资源的 `transferSize` 之和，包含响应头；脚本源码量包含
初始 HTML 的内联脚本与已加载外部脚本解压后的字节数。热缓存减少下载，不代表免除脚本执行。

### 冷加载 LCP 回退排查（2026-10-22，继续仅限本地）

本次以第一批优化后的 `.tmp/site-performance/after/dist` 为修复前基准，候选构建位于
`.tmp/site-lcp-investigation/after/dist`。原有两版构建和 80 次历史样本均保留，不将跨轮次
的绝对时间直接当作本次收益。继续使用相同的网络、CPU、缓存、视口与五组交替配对方法。

根因证据与修复边界：

- Chrome trace 中，长文章的主文档初始 Layout 约 1490ms，另有插图 SVG 的初始 Layout
  约 262ms；公共模块执行约 21ms，发生在主布局之后。首页初始 Layout 约 490ms，
  公共模块约 16ms。具体时长只是本机追踪样本，不能推导真实用户耗时。
- 因此没有证据将回退归因为粒子或公共模块体积。两代代码均存在完整文章首次布局的
  大任务，历史样本区间重叠、不同视口变化方向相反；尚不能证明第一批引入了稳定可复现的
  LCP 回退。单次耗时包含机器负载和浏览器调度的影响。
- 首页的 LCP 元素实际为页脚文字；标题有现有 opacity 入场动画。保留该动画，
  不将页脚 LCP 等同于标题完全可见时间，也不通过移除动画来改善分数。
- KaTeX 字体由布局后 CSS 使用才发现，诊断中约在导航后 660ms 发起；构成晚发现链路。
  三组预加载隔离实验将字体发起提前至约 43–67ms，但 LCP 有升有降，证明资源链路
  改善，尚不能证明它独自解释历史 LCP 回退。
- 隐藏二维码在首屏仍下载 49,585 字节图片体积（含头计量约 49,885 字节），与首屏资源
  共享带宽。改为原生 lazy 图片，打开二维码时正常加载，保持原图和现有交互。
- 曾隔离验证屏外块 `content-visibility:auto`：可缩短长文章布局，但需估计块高度，
  可能改变滚动进度和锚点定位，未纳入源代码。显式补充本机中文字体的实验结果不稳定，
  同样未采用；不调整字体选择、不替换 Markdown/KaTeX 引擎。

Decision: code-change。两个可操作的资源调度问题分别由共享布局与文章模板拥有，
本次只修改这两个资源生产位置，不增加全局加载管理器或依赖。属于独立的两处资源调度
改进；它们不等于已证明的历史回退原因。保留完整布局、评论延迟加载、特效参数及所有正文。

实现：共享布局增加可选 head 插槽，并在隐藏二维码声明 `loading="lazy" decoding="async"`。
文章模板依据 Astro 已生成的 KaTeX HTML，预加载实际使用的 Main、Math Italic、AMS
常用字体；使用包内 URL 导入，沿用原 CSS 的同一哈希资源和 CORS 模式，避免重复下载。
普通页面无公式预加载；不依赖可能过期的 frontmatter `math` 开关。

本机诊断证据：`.tmp/site-performance/diagnosis.json`、`trace-summary.json`、
`home-trace-summary.json`、`ablation.json`、`fonts-ablation.json`、`preload-ablation.json`。
隔离实验经 Playwright 路由替换响应，浏览器缓存行为与正式配对不同，只用于证伪或确认
资源依赖，不与正式冷/热缓存性能结果混用。
