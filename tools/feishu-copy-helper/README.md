# 文档复制助手

选中内容，按 Ctrl+C，按需要复制为保留格式、纯文本或 Markdown。支持飞书 / Lark、腾讯文字文档，也可以为普通网页单独开启复制增强。适用于 Chrome 和 Edge，由 [LeonZhangDev](https://github.com/LeonZhangDev) 维护。

当前版本：**2.4.0**。[产品介绍与下载](https://leonzk.cn/projects/feishu-copy-helper/) · [项目列表](https://leonzk.cn/projects/)

## 能做什么

| 模式 | 适合的用途 | 复制内容 |
| --- | --- | --- |
| 保留格式（默认） | 粘贴到 Word、飞书等富文本编辑器 | 纯文本和带常用样式的 HTML |
| 纯文本 | 记事本、搜索框、聊天输入框 | 选区原文，不主动清洗字符 |
| Markdown | 笔记、技术文档、代码仓库 | 标题、粗体、斜体、链接、列表、引用、代码块和普通表格 |

保留格式时，会读取原页面的字体、字号、颜色、高亮、对齐、段落间距和缩进，将编辑器正文还原为标题、列表和段落。复制时去掉多余排版容器，避免段落之间出现额外空行；原文空段落、段内软换行和代码块内部空行仍会保留。局部选择只复制选中的部分；输入框和文本框始终复制选中的原文。

图片默认保留引用地址。点击“准备选区图文复制”后，插件尝试内嵌选区内可读取的 PNG、JPEG、GIF、WebP 图片，再保持原选区按 Ctrl+C。每次最多 20 张，单张不超过 5 MB、总量不超过 20 MB；单张请求超时 5 秒，25 秒后不再发起新请求。弹窗会显示成功与失败数量，换选区后不会复用旧内容。图片仍受跨域、登录和原站权限限制。

合并单元格在保留格式模式下保留，Markdown 遇到合并表格时使用 HTML。无法还原的绘图或公式会给出提示。复杂布局和不同应用之间的排版差异仍需分别验收。

普通网页默认关闭增强。打开弹窗，点击“启用当前页面增强”，可改善文字选择、右键和复制被页面脚本拦截的问题；保留格式模式使用浏览器原生复制。粘贴增强需要单独勾选。“记住本站”会申请当前网站权限，授权后刷新也会自动启用，取消后移除该可选权限。

## 安装和更新

1. 下载发布包并解压，保留解压后的文件夹。
2. 打开 Chrome 的 `chrome://extensions/` 或 Edge 的 `edge://extensions/`。
3. 开启“开发者模式”，点击“加载已解压的扩展程序”。
4. 选择包含 `manifest.json` 的文件夹。
5. 回到飞书文档并刷新页面。

更新已有安装时，先在扩展管理页点击本扩展的“重新加载”，再刷新已经打开的文档。扩展详情中的版本应为 **2.4.0**。此前已复制到剪贴板的内容不会自动改变，需要重新选择和复制。

自动适配 `feishu.cn`、`larksuite.com` 及其文档子域名，以及腾讯 `docs.qq.com/doc/`、`docs.qq.com/aio/` 文字文档。腾讯表格、幻灯片、PDF、画布不在这一版的适配范围内，浏览器内部页面不能启用增强。

## 使用方法

打开扩展弹窗，选择保留格式、纯文本或 Markdown。设置按网站保存在浏览器本地，切换后会同步到本站其他已打开的文档，刷新页面后也会保留。

- 选中内容，按 Ctrl+C；macOS 使用 Cmd+C。
- 飞书和腾讯文档中，选中内容后右键可以临时使用另一种模式，不改变保存的设置。即使选区没有图片，也能复制为 Markdown。
- 双击普通文字，会选择所在元素的内容，并使用默认模式复制；输入框和可编辑区域保留浏览器原本的双击行为。
- 原有“复制清洁版本”和“超级清洁版本”仍在右键菜单中。它们会改变字符，需要保留原文时请选择纯文本模式。

弹窗通过脚本真实回应显示连接状态、版本、选区字符数，以及上次格式回退和图片准备结果。“已连接”表示页面脚本已初始化，不代表已取得文档管理权限，也不保证目标应用能保留所有格式。

## 遇到问题时

**显示“未连接到页面脚本”或“旧版脚本”**：重新加载扩展，刷新文档，再点“重新检测”。仅打开一个飞书网址，并不代表插件已经在页面上运行。

**粘贴后没有颜色或排版**：确认选择的是保留格式模式，并粘贴到支持富文本的编辑器中。记事本只接收纯文本，无法用来验收格式。

**段落之间有很多空行**：更新至 2.4.0，重新加载扩展并刷新文档，再重新选择和复制。新版清理了飞书正文的重复排版容器。

**图片没有显示**：尝试准备选区图片，查看成功与失败数量。只有可读取的图片能内嵌；直接复制的引用仍需要目标应用能访问原地址。

**普通网站仍拦截复制**：首次手动启用可能晚于页面的早期拦截。“记住本站”并刷新后，脚本会在页面加载早期运行。关闭增强会移除插件样式，恢复页面原本的行为。

**复制失败**：格式准备失败时会保留纯文本；主动复制的所有方案都失败时，会显示原文供手动复制，不会提示成功。快捷键使用浏览器真实复制事件，不依赖异步剪贴板权限。

## 本地数据与权限

`storage` 保存站点模式和开关，`activeTab` 用于当前页面操作，`scripting` 用于用户启用的网页。普通网站的长期访问权限仅在勾选“记住本站”时申请，未授权的网站不会自动注入脚本。

复制内容在本地处理，不存储复制历史，不接入 AI 服务，也不上传文档内容。准备图片会请求选区内的原图片地址；未准备的图片粘贴后，目标应用也可能请求原地址。插件不改变文档权限。

## 开发与测试

项目没有运行时依赖。核心文件如下：

- `copy-platforms.js`：识别平台和正文块语义。
- `copy-formats.js`：读取选区样式，生成 HTML、Markdown，按需准备图片。
- `content.js`：处理快捷键、复制事件、右键菜单和页面状态。
- `popup.html`、`popup.js`：切换模式、保存设置、检测页面连接。
- `background.js`：为已授权且记住的网站注册早期脚本。
- `manifest.json`：扩展配置。

无需安装依赖的逻辑测试和语法检查：

```powershell
node --test tests/copy-shortcut.test.cjs tests/popup-status.test.cjs
node --check copy-platforms.js
node --check copy-formats.js
node --check content.js
node --check background.js
node --check popup.js
```

在已安装 Playwright 和 Chromium 的环境中运行浏览器测试：

```powershell
node tests/copy-shortcut-browser.cjs . msedge
node tests/copy-modes-browser.cjs . msedge
node tests/copy-v24-browser.cjs output/v24-fixture msedge
```

也可以通过 Playwright MCP 调用脚本导出的函数。使用已有 Playwright 安装时，可用 `PLAYWRIGHT_MODULE` 指定模块路径；命令后两个参数分别为扩展目录和浏览器通道，不填时使用项目目录和 Chromium。

v2.4 夹具需先复制运行文件与 manifest 到 `output/v24-fixture`，仅为该夹具增加 `host_permissions: ["https://copy-generic.example/*"]`，用于自动检查站点注册。正式安装包没有这项预授权，浏览器原生授权提示仍需人工验收。

测试加载真实扩展，使用本地响应模拟飞书页面，不请求真实文档。浏览器检查覆盖实际 Ctrl+C/Ctrl+V、早期页面拦截、异步剪贴板禁用、常用格式、三种模式、跨标签页设置同步和真实消息握手。工具栏点击带来的 activeTab 网址授权在标签页形式的弹窗测试中由测试夹具补齐。

2026-10-22：2.4.0 已通过 18 项逻辑测试，以及 Edge 中的 17 项快捷键、33 项格式与模式、27 项 v2.4 浏览器检查。真实飞书文档完成 Ctrl+C → 独立本地富文本网页 Ctrl+V：5 段正文仍为 5 段，额外空段落为 0，正文字符一致。真实腾讯文字文档的格式和图片另行检查，详见 [开发进度](docs/progress.md)。浏览器内粘贴不替代 Word、WPS、Notion 等本机应用的人工验收。

2026-10-20：2.2 已通过 9 项逻辑测试和 16 项浏览器检查；用户在实际 Edge 飞书文档中手动完成 Ctrl+C → 记事本 Ctrl+V 验收，确认文字可以粘贴。该结论仅对应当时的纯文本场景。

打包时运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/package-extension.ps1
```

发布包只包含 8 个运行与说明文件。测试、浏览器会话、依赖、日志、本地配置和凭据不进入安装包；这些文件已加入 `.gitignore`。设计与适配说明见 [文档索引](docs/README.md)。
